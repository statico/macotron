macotron.homekit

Calls for Home accessories. Apple offers the HomeKit framework to iPhone, iPad, and Mac Catalyst apps, but not to native Mac apps like Macotron, so today these calls return no homes and cannot change an accessory.

const homes = macotron.homekit.homes();
if (!homes.length) macotron.notify.toast("Home", "No HomeKit homes");

Write HomeKit plugins so they handle an empty list. For lights and scenes today, call a shortcut that uses the Home app with macotron.shortcuts.

Calls

available(): boolean

Whether the HomeKit classes are present in the process. It can be true while homes() is still empty, so do not use it to decide whether accessories exist.

homes(): Array<{ id, name }>

The HomeKit homes. This returns [] today.

accessories(homeId?: string): Array<{ id, name, room, type, on?, value?, reachable }>

The accessories in one home, or in every home when you omit homeId. A row has the accessory's name, its room, its type, and whether it is reachable. Lights and switches add on; sensors can add a numeric value. This returns [] today.

set(id: string, state: { on?: boolean; value?: number }): { ok: boolean; error?: string }

Turns an accessory on or off, or sets its value. This returns { ok: false, error: "unavailable" } today.

See also

  • The homekit.js plugin, which shows "No HomeKit homes" until homes are available.
